这一阶段在学什么

这里是最朴素的向量检索：问题转向量 → 在库里找最近的 K 条 → 按相似度排序。 不加任何优化，所以它是一把尺子 —— 后面做混合检索、重排、查询重写， 都要拿这里的结果当对照，才知道到底提升没有。

观察两件事：

  • Top1 不一定是最能回答问题的。向量只算「语义像不像」， 分不清「讲了这个概念」和「回答了这个问题」。这次 Top1 是 「为什么这么做有效？」，而直接给答案的排在 #2。
  • 无关内容会混进来。相似度 0.58 这种分数，主题沾边但答非所问。 Top-K 里通常只有前 1-2 条真正有用，这就是后面要压缩上下文的原因。

相似度落在 0.5~0.7 之间很常见 —— 中文语义向量本身就在这个区间浮动， 绝对值不代表好坏，相对排序才是。

这一阶段在学什么

为什么加 BM25？ 向量检索算的是「语义像不像」，它分不清 Python 3.10 和 3.11； BM25 算的是「这个词出现了没有」，能精确命中 3.10 这种字面量。 两路互补：一个管「意思接近」，一个管「字面对上」。

为什么用 RRF 而不是加权求和？ 余弦相似度 0.62 和 BM25 分数 18.42 量纲完全不同， 没法相加（0.1 的余弦差等于多少 BM25 分？没人说得清）。RRF 只看排名， 把「第几名」换算成 1/(k+rank)，天然绕开量纲问题。

观察这个： 找一条 双路 标记的结果， 看它是不是在向量里排第 8、BM25 里排第 2，融合后顶到了第 1 —— 这就是「两边都说它相关」的加成。
反过来，标 仅 BM25 的那条， 通常是数字、编号、专业术语，向量模型完全没抓到。

⚠️ RRF 也有副作用：它会给「两路都出现但都排中游」的候选加分， 偶尔把不相关的顶上来。如果日志里出现 Top1 在两路里都不靠前 的黄色警告， 就是这个情况 —— 那正是阶段四「重排序」要解决的问题。

这一阶段在学什么

为什么要两段？ 交叉编码器太慢，不可能对全库跑。所以先用便宜的向量 + BM25 从几万条里粗筛出 20 条（召回），再用贵的重排模型逐条精判（精排）。 这就是工业界的标准做法：召回负责「不漏」，精排负责「准」。

双塔 vs 交叉编码器，差别在「query 和 doc 有没有见过面」：

  • 双塔（embedding）：query 编码一次、doc 编码一次，两个向量算距离。 doc 可以离线预算好，所以快 —— 但它俩从没见过面，只能比「整体像不像」。
  • 交叉编码器（rerank）：把 query 和 doc 拼在一起送进模型， 能看到「python」和「3.10」这两个词是怎么互相作用的。 所以慢，但能分清 3.10 和 3.11。

重点看「↑N」：一条内容召回时排第 13，重排后升到第 1 —— 这就是重排在做的事。 反过来，标「↓N」的被压下去了，说明它只是「字面沾边」但不是真答案。 如果出现「被挤出的候选」卡片，那些内容原本会被当成最相关喂给大模型。

实测：问「Python 3.10 有什么新特性」，3.10 那段 rerank 0.5287， 3.11 那段只有 0.1857 —— 向量检索分不出来的，这里分得清清楚楚。
